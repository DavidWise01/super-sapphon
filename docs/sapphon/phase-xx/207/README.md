# SAPPHON-207 — Vendor Bundle Preservation & Source-Owned Image Build Qualification

**Phase XX · Bound 7/8 · 87.5% source-design progress · operational recovery HOLD**

## Executive summary

SAPPHON-207 expands the Cargo.lock-only provenance work into byte-for-byte **vendor tree preservation**. GitHub Actions is configured to generate a real lockfile, run `cargo vendor --locked`, run a locked/offline Cargo check using the vendored registry sources, inventory every regular vendor file with SHA-256, and create a deterministic original tar archive. The report includes the lock SHA-256, canonical per-file list, tree digest, and exact archive SHA-256. A second verification reads and hashes the tar before upload. Only real files on the runner are accepted: placeholder hashes, symlinks, directory traversal, missing offline checks, or forged synthetic results do not qualify.

An optional image builder is configured separately, **only** when GitHub Actions repository variable `SAPPHON_RUST_BASE_IMAGE` contains a complete `registry/repository@sha256:<64 hex>` reference. It retrieves that base image, builds a local candidate with Docker `--network=none --pull=false`, and records the resulting local image ID and `docker save` archive hash. Those are source-owned build artifacts, not proof of a registry-published or independently attested image.

During authoring, the SAPPHON-206 commit-level PR workflow and combined-status queries returned empty arrays; they do not rule out push-triggered Actions. No genuine SAPPHON-206 artifact, original SAPPHON-205 lockfile, vendor tree, built image, passing runner, or live Pages execution was observed. **SAPPHON-207 is a committed qualification workflow, not certified runtime success.**

- `tools/test_sapphon_207_vendor.py`: **16 authored negative/positive synthetic cases** for deterministic output, tampering, symlinks, unsafe tar entries, missing original lock/offline checks and false image qualification.

## Distinct custody layers

1. **Authored source:** committed scripts, tests and workflow. This proves only file publication, not execution.
2. **Observed GitHub Actions:** if run successfully, produces actual Cargo.lock, vendor bytes, tar archive and hashes. These all share one owner/source ancestry.
3. **Locally built image:** a Docker image ID and `docker save` SHA-256 can show a specific owned build output, but the resulting image is not automatically a remote registry digest or independent external witness.
4. **Independent custody:** third-party keys, authenticated time and global anti-rollback have not been enrolled or observed.

SAPPHON-205's original artifact and SAPPHON-206's import results remain unverified during authoring, and SAPPHON-207 does not silently treat newly generated bytes as those historical originals.
